# Data Source: tfe_registry_module

Gets information about a public or private registry module.

-> **Note:** Since modules have a [required naming convention](https://developer.hashicorp.com/terraform/registry/modules/publish#requirements), you can get naming values from your module repository (`terraform-<module_provider>-<name>`).

## Example Usage

```terraform
# Basic usage

data "tfe_registry_module" "example" {
  organization    = "my-organization"
  name            = "no-code-ssm"
  module_provider = "aws"
}
```

### Nested Schema for `vcs_repo`

Read-Only:

- `branch` (String) The git branch used for publishing when using branch-based publishing for the registry module. When a `branch` is set, `tags` will be returned as `false`.
- `display_identifier` (String) The display identifier for your VCS repository. For most VCS providers outside of BitBucket Cloud and Azure DevOps, this will match the `identifier` string.
- `github_app_installation_id` (String) The installation id of the Github App. This conflicts with `oauth_token_id` and can only be used if `oauth_token_id` is not used.
- `identifier` (String) A reference to your VCS repository in the format `<organization>/<repository>` where `<organization>` and `<repository>` refer to the organization (or project key, for Bitbucket Data Center) and repository in your VCS provider. The format for Azure DevOps is `<ado organization>/<ado project>/_git/<ado repository>`.
- `ingress_submodules` (Boolean) Indicates whether submodules should be fetched when cloning the VCS repository.
- `oauth_token_id` (String) Token ID of the VCS Connection (OAuth Connection Token) to use. This conflicts with `github_app_installation_id` and can only be used if `github_app_installation_id` is not used.
- `repository_http_url` (String) The browsable HTTPS URL of the VCS repository.
- `service_provider` (String) The VCS service provider type. Valid values include `github`, `github_enterprise`, `gitlab_hosted`, `gitlab_community_edition`, `gitlab_enterprise_edition`, `bitbucket_hosted`, `bitbucket_data_center`, `bitbucket_server`, `ado_server`, `ado_services`.
- `source_directory` (String) The path to the module configuration files within the VCS repository. This feature is currently in beta and is not available to all users.
- `tag_prefix` (String) The prefix to filter repository Git tags when using the tag-based publishing type in a repository that contains code for multiple modules. Without a prefix, HCP Terraform and Terraform Enterprise publish new versions for all modules with valid Git tags that use semantic versioning. This feature is currently in beta and is not available to all users.
- `tags` (Boolean) Specifies whether tag based publishing is enabled for the registry module. When `tags` is set to `true`, the `branch` must be set to an empty value.
- `tags_regex` (String) Read-only echo of any tags regex stored on the VCS repository.
- `webhook_url` (String) The inbound webhook URL registered with the VCS provider. This is the HCP Terraform or Terraform Enterprise endpoint that the VCS provider calls on push or pull-request events.
